# E015 · 단독 Waves와 FM–Waves 양방향 교환

고정 소스의 [공식 예제 07](../replay/coupling-cases.md)에서 단독 Waves 모델을 준비하고 설치된 DIMR/Waves/SWAN으로 두 번 계산했다. 두 경우의 Wave 입력 파일 중 `obw.mdw`만 다르다. 세 경계의 `WaveHeight`를 모두 1.5 m에서 0.75 m로 낮췄다. FM 구성요소는 없다.

| 원본 NetCDF에서 대조한 값 | 기준 | 경계 파고 절반 |
| --- | ---: | ---: |
| map `hsign` 최대 (m), 2시각 × 75 × 66 | 1.5020 | 0.7508 |
| history `Hsig` 최대 (m), 2시각 × 2관측점 | 1.49727 | 0.74864 |

두 사례의 실제 시각은 2000-07-14 00:00 및 01:00 UTC였다. map의 시간·마스크를 맞춰 직접 대조한 9,900개 값 모두 기준군이 컸고, 같은 위치·시각에서 최대 차이는 **0.751200 m**였다. 독립 시험은 `E015-V-native-slot17-20261104-01`, 새 폴더에서 입력 준비부터 다시 실행한 통합 시험은 `E015-G-waves-final-01/verification.json`(SHA-256 `16806f7a0d436b956dad502f63a07a6611ed855d523f07d599329df008d2e564`)이다. 두 폴더 모두 `research/experiments/` 아래에 있다.

재현: [준비 함수](../../workflows/verification/verify_coupling_prepare.py)의 `prepare_wave_cases(source, new_folder)`에 고정 소스의 예제 묶음과 새 폴더를 지정한다. 그 안의 `prepared/waves_candidate`와 `prepared/waves_half_height`를 각각 `dfm coupling run CASE --install SUITE --out NEW --timeout 120`로 실행한다. [독립 검증기](../../workflows/verification/verify_coupling.py)의 `--plan PLAN --root ROOT`는 보존된 출력만 읽는다. 기준·변경 입력의 차이, 실행 인자, 원시 출력 검사는 통합 시험 폴더에 있다.

예제 08은 별도 시험이다. 첫 FM–Waves 계산은 SWAN의 `PRINT`에서 무풍과 quadruplet 상호작용의 조합을 거부했고 DIMR이 종료 코드 1을 반환했다. 이 경우 정상 파고장이나 양방향 교환을 확인하지 못했다. 단독 결과는 FM–Waves 결합, RTC, 수질, 취소 격리 또는 현장 파랑 정확도를 입증하지 않는다.

수정된 08의 다음 시험 `E015-V-native-slot21-20261104-01`은 네이티브 종료 코드 0이었지만 공개 CLI가 종료 코드 6을 반환했다. 실제 FM map(`s1`, m)은 0–7,200초에 13개, Waves map(`hsign`, m)은 0·3,600초에만 두 샘플이 있었다. 두 컴포넌트 모두에 7,200초의 샘플을 요구한 원래 선언은 실패한 그대로 둔다. `E015-V-clock-contract-20261104-01/clock-contract.json`은 DIMR 제어 순서·Waves의 호출 시각·실제 파일을 대조한다. 구간 시작에서만 호출되는 모델을 지원할 때는 시각 규칙을 입력에 명시하고 FM 종료 시각, 파랑을 마지막으로 계산한 시각과 다음 호출까지 적용한 구간을 따로 표시해야 한다.

`E015-V-native-slot25-20261104-01`은 Waves의 구간 시작 시각을 명시해 파일·시각 검사를 통과했다. 하지만 첫 SWAN 풀이에서 40회 반복 뒤 수렴한 젖은 지점은 94.26%로 사전 목표 98%에 못 미쳤다. `E015-V-native-slot27-20261104-01`에서 반복 한도를 120과 200으로 올려도 기준군의 첫 풀이는 56회에서 98.86%로 같았다. 경계 파고 절반 대조군도 기준을 충족했다. 반면 FM의 수위·유속 피드백을 끈 대조군은 200회 후 두 풀이에서 92.80%, 94.40%였고 통과하지 못했다. 세 경우 모두 물리 대조에 쓸 수 있다는 판정은 내리지 않았다.

## 예제 08: 두 교환 방향을 서로 다른 대조군으로 분리

기준군과 두 변경군을 모두 새로 실행했다. 세 모델 모두 FM 시각은 0부터 7,200초까지 600초 간격, 정상류 파랑 해를 계산한 시각은 0·3,600초다. 마지막 7,200초의 파랑 샘플은 없다. SWAN의 여섯 풀이 모두 미리 정한 젖은 지점 수렴 기준 98%를 충족했다.

| 단 하나의 입력 차이 | 원본 NetCDF에서 확인한 반응 (같은 지점·시각 최대 절대차) |
| --- | --- |
| Waves 경계 파고 1.10 → 0.55 m, FM 입력 동일 | 파랑 유의파고 차이 0.5568 m, FM 수위 차이 0.0312152 m. 최초 FM 수위는 동일했다. |
| FM의 `L1_0007` 수위만 1,800초부터 올려 3,600초에 +0.20 m, Waves 입력·실제 SWAN 경계 명령 동일 | 파랑 격자의 첫 수심·유속·파고는 같았다. 3,600초에 받은 수심 차이 0.1480 m, x/y 유속 차이 0.0254/0.1600 m/s, 유의파고 차이 0.0650 m. 두 시각의 바람은 동일했다. |

독립 시험 `E015-V-native-slot31-20261104-01`과 통합자 시험 `E015-G-08-exchange-01`에서 같은 판정을 얻었다. 통합 `verification.json` SHA-256은 `16b59418e65ae9d734fd71c89adffb98b5c71d304448be1ba3529225068ea940`다. 통합자가 제품과 검증기를 통하지 않고 여섯 원본 map에서 시계·마스크·차이를 다시 읽은 결과는 같은 폴더의 `coordinator-raw.json`이다. [독립 재현기](../../workflows/verification/verify_coupling_hydraulic.py)의 `prepare`는 새 입력을 만들고, `run`은 새 폴더에서 공개 명령으로 세 경우를 실행한다.

**승인 범위:** 이 08 변형에서의 양방향 물리 반응과 예약 시각이다. 정상 종료한 job의 마지막 소유 목록은 모두 비었다. 중단된 계산의 부분 출력은 완료된 파랑장이나 재시작 입력으로 인정하지 않는다. SWAN에서 경계 입력과 계산 파고 사이에 상대 차이 10% 이상인 지점 경고가 남았다. 수렴 기준 통과는 현장 파고의 정확도를 보증하지 않는다.

## 같은 DIMR 실행 파일을 쓰는 두 모델 중 하나만 중단하기

각 경우에 별도 입력 복사본·작업 폴더·Windows Job으로 두 개의 `coupling run`을 시작했다. 대조군과 대상의 DIMR 파일 지문은 같았고 PID·생성 시각·소유자는 달랐다.

| 대상에 한 조작 | 대상의 실제 결과 | 같은 바이너리의 대조군 |
| --- | --- | --- |
| SWAN 자식이 살아 있을 때 공개 `run cancel` | `cancelled`. 요청 때 열어 둔 `swan_omp.exe` 핸들의 프로세스가 종료됐고, 대상 job의 종료된 멤버 목록에서도 같은 PID와 실행을 확인했다. | 대상 종료 뒤에도 살아 있었고 정상 완료 |
| 2.5초 wall timeout | `timed_out`. 취소 요청과 구별됐고 job 종료 확인 | 대상 종료 뒤에도 살아 있었고 정상 완료 |
| 복사본의 SWAN 격자를 고의로 손상 | 네이티브 계산이 오류를 내고 `failed`로 종료 | 대상 종료 뒤에도 살아 있었고 정상 완료 |

세 대조군 모두 원본 FM map이 7,200초에 도달했고, 파랑 map에는 예정된 0·3,600초가 있었다. 검증기는 PID 조회만으로 종료를 판정하지 않고 보관한 핸들과 job 멤버, 대조군의 최종 파일을 함께 검사했다. 확인한 피실험체는 이 Windows 08 사례뿐이다. 강제 종료가 결과 파일의 정상 마감을 보장하지 않는다.

독립 시험 `E015-V-cancel-native-slot39-20261104-01`, 통합 시험 `E015-G-coupled-stop-01/verification.json` (SHA-256 `8966ff4872d1db3e66abf4b6da85851032164e3a71a1dfdc26dc333478d0ca4f`). [재현기](../../workflows/verification/verify_coupling_cancel.py)의 `prepare`로 대조군과 손상 격자를 만들고, 할당된 슬롯에서 `run`을 호출한다.
