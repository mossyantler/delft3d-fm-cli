# 관측 단면 단독 교환 후보 검수 — G18

2026-11-05. **별도 설치 후보의 파일 작업 검수까지 통과했다. 루트 제품 병합, 실제 엔진 대조, GUI 단독 가져오기·내보내기는 아직 승인하지 않았다.** 구현은 Nash, 독립 파일 검증은 Lovelace, 후속 수치 대조 계획은 Mill, 최종 통합은 오케스트레이터가 맡는다.

## 구현한 파일 작업

후속 엔진 대조 준비는 [Mill의 동결 자료](../../experiments/G18-NATIVE-PLAN-V-20261105-01/freeze.json)와 [통합자 재검수](../../experiments/G18-NATIVE-PLAN-G-final-01/verification.json)를 통과했다. 기준/전체 왕복, 수동/공개 append, 수동/공개 replace의 여섯 입력과 독립 판독기를 고정했다. 동결 파일 103개 및 입력 60개 지문을 확인했고 합성 검사 28개를 재실행했다. 각 계산의 600초, 초기·최종 restart, 191변수, 단면 이름·정점·부호·비대상 결과를 대조할 계획이다. 실제 엔진 결과는 아직 없으며 공용 실행 수정이 먼저다.

고정 [G18 계약](../../experiments/G18-PROPOSAL-I-20261105-01/contract.json)에 따라 한 MDU가 가리키는 기존 관측 단면 PLI를 다룬다. 현재 후보는 `section export`와 `section import`를 추가한다. 기존 단면 방향 편집의 판독기와 계약은 바꾸지 않는다.

| 작업 | 파일과 보존 기준 |
| --- | --- |
| 전체 내보내기 | 지원 범위 안의 PLI 전체 바이트를 새 외부 파일에 복사. 기존 출력 덮어쓰기 금지 |
| 선택 내보내기 | 정확한 전체 이름으로 선택. 인자 순서와 관계없이 원본 단면 순서 유지. 선택한 단면 블록을 그대로 복사하고 제외한 주석·공백 구간을 보고 |
| append 가져오기 | 충돌 없는 이름의 단면만 추가. 기존 마지막 블록 뒤, 파일 꼬리 주석 앞에 삽입. 필요한 줄바꿈만 명시적으로 보고 |
| replace-matching 가져오기 | 선택한 모든 이름이 기존 대상과 정확히 일치해야 함. 대상의 블록 위치와 비대상 바이트 보존 |
| 무변경 적용 | 바이트가 이미 같으면 입력·소스·경로·권한을 다시 검사하고 게시하지 않음. 파일 식별자와 수정 시각 유지 |

가져오기의 `--coordinates model-xy-as-is`는 호출자의 좌표 선언이다. 좌표계·단위·수직 기준의 호환성을 검증하거나 좌표를 변환하지 않는다. 이름 충돌의 casefold 거부는 CLI 정책이며 GUI나 엔진의 동일성 규칙으로 주장하지 않는다. 지원 텍스트 형식·길이·경로·중복·기하 제한은 계약과 schema에 명시했다.

## 근거

고정 후보는 `G18-TRANSFER-I-20261105-rev02`, wheel SHA-256은 `63e4b869d5afd9305f9239236dacaa5604aee883cbb0e873971bc319837b0a7e`다. 제품 196파일 중 기존 189파일은 같고, 명령 등록 두 파일을 수정하고 새 모듈 다섯 개를 추가했다. 기존 명령 98개와 옵션·메타데이터를 유지한다.

- [독립 설치 검증](../../experiments/G18-TRANSFER-V-20261105-01/final-01/verification.json): G18 파일·게시 검사 39개, 외부 부모 디렉터리 식별자 검사 2개, 기존 G12 회귀 24개. 건너뜀 없음. 외부 공개 명령 137회와 프로세스 내부 오류 주입 호출 38회를 구별해 기록했다.
- [최종 동결본 연결 확인](../../experiments/G18-TRANSFER-V-20261105-01/release-snapshot-01/verification.json): 선언한 469파일, 기존 hold·wheel·독립 검수 근거의 바이트가 일치한다.
- [통합자 설치 명령 대조](../../experiments/G18-TRANSFER-G-installed-01/verification.json): 원래 f34 입력 10개를 복사해 12회 호출. 전체/선택 export, 원본 순서, 무변경 식별자·수정 시각, 마지막 줄바꿈이 없는 블록의 append와 꼬리 주석 보존, 충돌·오래된 동의 거부, 나머지 9입력 보존을 확인했다. 원래 자료는 바꾸지 않았다.

독립 검증은 실제 Windows DACL·보안 기술자 보존과 변경 감지, 같은 크기·복원된 수정 시각에도 달라진 바이트 거부, 같은 바이트로 교체된 파일 식별자 거부, fsync 이후 변경과 게시 경합을 포함한다. 오류 뒤에는 실제 게시·복구·임시 파일 소유 여부를 보고하며, 확인 불가 상태를 성공이나 원본 불변으로 바꾸지 않는다. 처음 실패한 검사 기록은 남겼고 잘못된 테스트 입력 및 주입 시점 두 건의 수정 이유와 재검사 범위도 기록했다.

## 합류 전에 남은 일

Mill이 기준/전체 왕복, 수동/CLI append, 수동/CLI replace의 여섯 사례를 독립 준비한다. 입력의 정확한 바이트뿐 아니라 실제 history의 단면 이름·순서·형상·유량 단위와 시계열을 대조해야 한다. 방향 반전 사례의 부호와 비대상 신호는 별도 사전 기준을 따른다. 기존 G12 실행 승인을 단독 교환 작업에 전용하지 않는다.

실제 공개 `short` 실행은 [종료 판정 수정](serial-close.md)의 새 후보 검수를 선행 조건으로 둔다. GUI가 제공하는 형식·충돌 정책·프로젝트 저장 시점은 이 파일 작업의 통과 결과로 확인되지 않는다. 루트 명령 등록, 문서·예제·테스트 병합은 최종 합류 검수 후 오케스트레이터가 수행한다.
