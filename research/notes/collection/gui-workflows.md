# GUI·콘솔 작업과 엔진 파일 대응표

**대상:** Windows Delft3D FM Suite 2026.02 OpenHMWQ, FlowFM 플러그인 4.19.0.9954. CLI 0.3.1을 출발점으로, 2026-11-05 개발판 `0.4.0.dev1`의 `dfm schema inspect`와 [M1–M5 검수](../verification/roadmap-2d.md)를 대조했다. **82행은 작업 목록이지 검증한 GUI 기능 수가 아니다.** 같은 작업을 리본·트리·지도에서 시작해도 한 번만 센다. X06–X10은 GUI 바깥의 수동 설정·외부 도구와 구별하기 위해 포함했다.

**읽는 법.** 파일 열의 ‘읽기’와 ‘쓰기’를 구별했다. 편집기에서 값을 바꾸는 순간과 저장·내보내는 순간도 다르다. **호스트 실험이 없는 행의 파일은 문서·엔진 판독 코드에서 찾은 대상 또는 후보**다. 설치된 GUI가 실제로 다시 쓴 파일 목록으로 해석하지 않는다. 엔진 열에는 내보낸 입력을 *읽는* 코드, 결과 보기 작업에는 원자료를 *쓰는* 코드를 연결했다. GUI가 그 함수를 직접 호출했다는 뜻이 아니다. 화살표 없는 ‘없음’은 Shell에서 끝나는 작업, ‘미확인’은 아직 연결을 입증하지 못한 작업이다.

- **호스트 근거:** **G** = 새 GUI 프로세스에서 스크립트로 재현, **C** = 별도 콘솔에서 재현, **화면** = 해당 항목이 보인 것만 확인, **정적** = 설치된 프로그램/도움말 조사, **문** = 매뉴얼. **실행** = CLI 또는 직접 엔진 실험이며 GUI 실행 증거와 별개다. G/C 실험은 대화상자를 클릭한 시험이 아니다.
- **CLI 열:** 명령은 `dfm` 뒤에 붙여 쓴다. **현재/부분**은 명시한 입력·동작 범위에서만 사용 가능하다. **실험 중**은 명령이 있어도 수치나 실행 동등성을 검증 중인 상태, **계획/미지원**은 대응 명령이 없는 상태, **제외**는 화면 자체 등 제품 범위 밖이다. 1D2D와 2D3D는 커널을 공유하지만 GUI가 다르다(FM §1.1 PDF p.27). 한쪽의 메뉴나 콘솔 API를 다른 쪽에서 확인한 것으로 세지 않는다.
- **근거 위치:** FM = *D-Flow FM User Manual* 2026.02, DS = *Delta Shell User Manual* 2026.02. 아래 p.는 **PDF 페이지**다. [로컬 매뉴얼·원본 색인](../../README.md), [버전 잠금](../../sources.lock.json). 소스 링크는 모두 Delft3D `DIMRset_2026.02`의 고정 커밋 `5a4649830b1e5072caf019fb4850bbdefd9ad431`에 연결한다. 설치 FM은 `1.2.184.Unknown`으로, 동일 커밋의 빌드인지 확인되지 않았다.

AI에서 특정 작업만 읽으려면 저장소 루트에서 `python -m research.workflows.collection.gui_workflows P04 B02 R02`를 실행한다. ID를 생략하면 전체 표를 UTF-8 JSON으로 출력한다. `files`에는 실측과 예상의 구분이, `evidence`에는 확인 방법과 미검증 범위가 남는다. 이 조회는 GUI나 엔진을 실행하지 않는다.

**f34에서는 어느 파일이 실제로 달라졌나?** 아래는 남겨 둔 두 번째 재현의 파일 내용(SHA-256) 비교다. 새 폴더에 파일을 쓰는 것과 그 파일의 내용이 대조군과 달라지는 것을 구분했다.

| --- | --- | --- |
| 공식 f34를 가져와 설정 변경 없이 GUI에서 처음 내보내기 (P01 → P04) | [가져오기 전 입력](../../experiments/E001-E002-replay-20261103/source-input/f34.mdu)과 [첫 export](../../experiments/E001-E002-replay-20261103/gui-export-1/f34.mdu)의 파일명 10개가 일치한다. 비MDU 9개는 SHA-256도 같다. EXT의 `[Boundary]`는 위치 `f34_001.pli`와 신호 `f34_001.bc`를, `[Meteo]`는 바람 `f34.wnd`를 가리킨다. [편집 실험][edit]에는 무변경 대조군과 구간별 diff가 있다.

**M1의 한 셀을 추적하는 예.** f34 프로젝트를 다시 연 뒤 콘솔에서 `L1`의 0번 지원점, 주파수 28.8도/시간의 진폭을 1.5 m에서 1.75 m로 바꿨다. 내보낸 파일에서는 `f34_001.bc`의 `L1_0001`, 주기 750분, 15행에 해당한다. FM은 [MDU의 새 EXT 경로][extnew] → [경계의 위치·신호 파일][bnd] → [BC의 조화 성분 열][harm] 순서로 이 값을 찾는다. 콘솔 export에서는 같은 블록의 공백과 MDU 생성 시각도 바뀔 수 있다. [공개 CLI의 직접 편집][gates]에서는 그 숫자 바이트만 달라졌고, 기준군과 변경군 모두 600초에 도달했다. 이 행을 재현해도 경계점 추가·삭제나 GUI 지도 스냅까지 확인한 것은 아니다.

## 작업별 승인 기준

한 작업의 상태를 단일 ‘완료’로 합치지 않는다. 아래 다섯 항목은 독립적으로 판정하며, 해당 근거가 없으면 미검증으로 남긴다. 상세 표의 호스트 근거와 CLI 열을 함께 읽어야 한다. 비공개 시험 패키지가 통과했어도 현재 제품에서 제공하는 명령으로 표시하지 않는다.

| 판정 대상 | 필요한 증거 | 이 증거만으로 확인할 수 없는 것 |
| --- | --- | --- |
| GUI 조작 | 새 프로젝트 복사본에서 해당 메뉴·속성 조작, 무변경 대조 export와 파일 차이, 필요 시 저장·재열기 | 같은 API를 호출한 콘솔의 동작, 다른 메뉴의 동등성 |
| 콘솔 조작 | 스크립트·설정·설치 버전, 완료 표식, 생성 파일과 값·참조 확인 | GUI 대화상자 동작. 종료 코드 0만으로는 스크립트 성공도 확정하지 않음 |
| 입력 파일·CLI 편집 | 공개 명령의 미리보기·적용, 목표 값과 비대상 바이트 보존, 낡은 지문 거부, 참조 무결성 | 엔진이 해당 값을 실제 계산에 사용했는지 |
| 엔진 실행 | 선택 바이너리·입력 해시·인자, 종료 및 소유 프로세스 정리 증거, 요청 최종 시각과 실제 출력 시각 | GUI 실행 경로, 수리·수질 결과의 타당성 |
| 결과 대조 | 독립 판독기로 수동 대조군과 변수·단위·좌표·시각·결측·restart 비교, 사전 정의한 허용 오차 | 다른 모델·버전·물리 과정으로의 일반화 |

새 작업을 맡을 때는 기존 ID 아래에 **변경할 값 하나, 무변경 대조군, 예상 변경 파일, 보존할 파일, 위 다섯 판정 중 이번에 확인할 항목**을 먼저 적는다. 실제 결과가 예상과 다르면 원본 증거와 실패 판정을 보존하고 파일 연결·CLI 범위를 수정한다. 구현 우선순위와 미확인 GUI 경로는 [로드맵 M0](../../../ROADMAP.md)에서 관리한다.

## 범위 점검 및 M1 착수 기준

- **대조 기록(2026-11-05):** 82개 작업 ID, 각 행의 다섯 열, 로컬 자료 링크를 확인했다. 고정 커밋의 28개 파일에서 110개 소스 위치를 확인했다(병합 도구 실행 스크립트 포함). CLI 열에서 그룹·하위 명령으로 식별한 80종은 개발판 `dfm schema inspect`에 등록돼 있다. [목록 대조 결과](../../catalog/gui-workflows-audit.json)에 확인 범위를 남겼다. 등록 여부와 동작 검증은 별개다. [f34의 다섯 쌍](#f34-file-diffs)은 각 10개 파일의 SHA-256으로, [E012의 분할·병합 지도](#results-file-actions)는 보관된 NetCDF 세 개의 면 수와 시간축으로 대조했다. S07은 두 MDU의 세 키와 바람 파일의 해시로 확인했다. B06의 직접 엔진 결과는 GUI 검증에 합산하지 않는다.
- **분모:** 설치 화면에서 보였던 FM 트리([초기 조사][host]), FM 매뉴얼 §7.4.1–16 전체와 저장/실행/결과(§§7.5–9), DS §§3–8의 작업군을 대조했다. General/Area/Grid/Bed → G01–G08; Time/Processes/Initial → S01–S03; Boundary → B01–B04/B09–B14; Physical → S04/S07/B05; Sources/Intakes/Laterals → B06–B07; Numerical/Misc/3D → S05–S06; Output parameters/Output → O01–O04/V01–V02. Shell 프로젝트·공간 연산·스크립팅·통합 모델 → P/G02/X. Region 편집기의 하천 단면 가져오기는 G09로, 펌프 방향 반전은 G13으로, 독립 XYZ 점군 등록은 G14로 분리했다. 구조물 형식별 교환·가동보 CSV·외부 격자 편집기 왕복은 G15–G17, 관측 단면 단독 교환은 G18이다. 표시 전용 동작도 V04에 남겼다.
- **대조 범위:** 프로젝트 12, 공간 자료 18, 시간·물리 7, 경계·외력 14, 출력 설정 4, 실행 11, 결과 관리·보기 6, 통합·선택 모듈 10개 작업이다. 각 ID는 한 번만 쓰며, 소스 링크는 고정 커밋의 파일과 행을 가리킨다. 이 숫자는 GUI 지원률이 아니다.
- **남은 빈칸:** 작업군 목록이지 모든 아이콘·컨텍스트 메뉴·선택 플러그인의 전수 런타임 시험이 아니다. 예를 들어 공간 스택 저장 파일(G02), 취배수별 파일(B06), GUI Run의 helper argv와 중단 방식(R01/R05), 통합 export(X01)는 아직 확정할 수 없다. 새로 확인하면 **한 복사본에서 한 동작** 전후를 비교해 해당 ID에 설치 버전·파일 diff·실험 링크를 붙인다. GUI에서만 가능한 동작을 콘솔에서도 가능하다고 전파하지 않는다.
- X06–X10은 매뉴얼로 찾은 전문 영역이다. 특히 기포막(X07)은 이 판본에서 GUI 편집 기능이 없다고 명시한다. 다른 행의 ‘미확인’은 이처럼 명시적인 ‘미지원’과 다르다.
- **M1의 경계:** B01의 **조회**와 B02의 **기존 harmonic 진폭 변경**만 구현·검증했다. B03의 다른 함수·보정 및 B04의 경계 객체 import/export, B09/B10의 신호 병합·삭제는 별도다. 기준군/변경군의 실제 엔진 실행은 R02와 연결하되, E005 자체는 solver를 실행하지 않았다. [M1 검수](../verification/roadmap-2d.md)에서 두 실행의 최종 600초를 확인했다.
